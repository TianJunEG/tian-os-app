# MathPath Diagnostic Accuracy & Evidence Validation

## Executive Summary

This sprint adds a validation layer for the central educational question:

> Can Tian OS justify each weak-skill and intervention recommendation with evidence?

The system now supports:

- per-skill diagnostic validation
- evidence confidence scoring
- false-positive risk detection
- false-negative risk detection
- cross-evidence agreement checks
- intervention validation from Recovery Pack to Recheck
- admin validation report at `/admin/diagnostic-validation`

Current verdict: partially validated. MathPath has enough data structures to audit diagnostic conclusions, but some skills still need stronger misconception-specific probe items before every intervention recommendation can be defended at high confidence.

## Skill Validation Matrix

The validation matrix is generated by `services/mathpath/diagnosticValidationEngine.js`.

For each completed diagnostic and skill, the matrix reports:

- questions used
- misconceptions targeted
- evidence strength
- confidence score
- confidence level
- supporting evidence
- alternative explanations
- false-positive risk
- false-negative risk
- intervention linkage

Evidence sources:

```text
Diagnostic
Paper Analysis
Working Evidence
Recovery Pack Performance
Recheck
```

## Diagnostic Evidence Audit

| Evidence Area | Current Support | Weakness |
| --- | --- | --- |
| Per-skill score | Supported through `perSkillSnapshot`. | Some sessions may have only 1 item for a skill. |
| Question count | Supported from snapshot or attempts. | Single-question conclusions are flagged as weak evidence. |
| Confidence | Supported through attempt confidence fields. | Confidence vocabulary varies across older records. |
| Timing | Partially available on attempts. | Not yet weighted strongly in validation. |
| Working evidence | Supported through `workingSubmitted`, `workingNotNeeded`, working insights. | Depends on OCR/step extraction quality. |
| Paper evidence | Supported through `PaperAnalysis`. | Adult confirmation is required for strong evidence. |
| Assignment evidence | Supported through `MathPathAssignment`. | Recovery Pack completion is not always followed by recheck. |
| Recheck evidence | Supported through diagnostic sessions with `diagnosticPurpose: recheck`. | Recheck linkage to assignment is incomplete for older data. |

## Skill Identification Validation

Weak-skill identification is strongest when:

1. at least 3 diagnostic questions support the skill conclusion
2. per-skill snapshot exists
3. wrong answers are consistent
4. paper analysis also confirms the skill
5. working evidence shows method issue
6. recovery pack or recheck evidence aligns

Weak-skill identification is flagged for review when:

- only one question was answered
- the student got more correct than wrong
- external paper evidence conflicts with the diagnostic
- confidence is mismatched
- working is missing on high-reasoning questions

## Misconception Validation

The system can distinguish these categories at a first-pass level:

- conceptual error
- procedural error
- careless error
- confidence mismatch

Weak areas:

- Careless vs conceptual errors require clearer working steps.
- Some misconceptions are currently inferred from text patterns rather than dedicated diagnostic probes.
- Older attempts may lack consistent confidence and working metadata.

## False Positive Audit

False-positive risk means the diagnostic says a skill is weak but evidence is thin.

Common risk patterns:

- `single_question_evidence`
- inconsistent confidence
- only one wrong answer
- overlapping prerequisite skills
- no supporting paper or working evidence

Recommended handling:

- collect one more diagnostic probe
- use a parallel item
- compare with paper and working evidence before assigning heavy remediation

## False Negative Audit

False-negative risk means the diagnostic says a skill is secure but the student may still be weak.

Common risk patterns:

- lucky correct answer
- correct but low confidence
- high-confidence wrong answer elsewhere
- poor working despite correct final answer
- paper analysis conflicts with diagnostic
- recovery pack performance remains weak

Recommended handling:

- schedule retention review
- assign a short recheck
- route to manual tutor/parent review when evidence conflicts

## Cross-Evidence Validation

`services/mathpath/crossEvidenceValidator.js` compares:

- diagnostic signal
- paper analysis signal
- working evidence signal
- assignment signal
- recheck signal

Output:

- agreement score
- dominant signal
- source conflicts
- confidence level
- requires review

Example:

```text
Diagnostic: F011 weak
Paper Analysis: F011 weak
Working Evidence: method issue
Agreement: high
Action: assign targeted practice
```

## Intervention Validation

`validateInterventions()` checks:

```text
Recovery Pack
  -> Recheck
  -> Skill improvement
```

It reports:

- intervention success rate
- unresolved misconceptions
- pending rechecks
- targeted skill improvement

Current limitation:

Older assignments may not have a completed recheck, so success rate can be understated.

## Evidence Confidence Score

The Evidence Confidence Score is 0-100 and combines:

- diagnostic evidence
- paper evidence
- working evidence
- assignment evidence
- recheck evidence

Low confidence is flagged when:

- evidence comes from too few questions
- sources conflict
- no adult-reviewed paper evidence exists
- no working/recheck evidence exists

## Recommended Fixes

Priority 1:

- Add misconception-specific diagnostic probe items for high-impact skills.
- Ensure every diagnostic item records confidence, timing, skip, and working metadata.
- Enforce minimum evidence count before marking a skill weak with high confidence.

Priority 2:

- Link Recovery Packs to Rechecks more consistently.
- Weight timing and confidence calibration in the validation score.
- Add adult-reviewed paper evidence into the intervention confidence score.

Priority 3:

- Build evidence lineage views for parents/tutors later, after validation quality is stable.
- Add domain-agnostic evidence validation once a second subject is live.
