# MathPath Student Pilot Preparation v1.0

## Purpose

This document prepares Tian OS MathPath Fractions for a supervised small student pilot.

Goal:
- Validate that real students can use the Fractions vertical reliably.
- Validate that MathPath captures usable learning/outcome data.
- Surface blockers before any broader rollout.

---

## Pilot Scope

- Pilot size: **5–10 students**
- Domain: **Fractions only**
- Duration: **4–8 weeks**
- Levels: **Primary 3 to Primary 6**
- Pilot mode: **Supervised internal pilot** (founder/team monitored)
- Environment: **Staging/dev pilot environment only**

---

## Pilot Structure

Each student follows this sequence:

1. Baseline diagnostic
2. Baseline assessment (if available in current environment)
3. Weekly practice sessions
4. Weekly fluency sessions
5. Retention review checkpoints
6. End-of-pilot assessment
7. Parent feedback collection

---

## Pilot Workflow (Operational)

### Week 0 (Setup + Baseline)
- Confirm account + device readiness
- Run baseline diagnostic
- Run baseline assessment (if enabled)
- Record initial starting skill and weak skill list

### Weeks 1–6 (or pilot duration weeks)
- Run scheduled practice sessions
- Run short fluency sessions
- Track retention review completion
- Log bugs and intervention notes weekly
- Send parent progress check-ins

### Final Week (Closeout)
- Run end-of-pilot assessment
- Export outcome summary
- Collect parent + student feedback
- Conduct pilot exit review

## Pilot Checklists

## 1) Student Onboarding Checklist
- [ ] Student selected within P3–P6 range
- [ ] Student briefed on pilot objective and weekly routine
- [ ] Student can log in independently
- [ ] Student understands answer input and session completion flow
- [ ] Student knows who to contact for help

## 2) Parent Consent Checklist
- [ ] Parent informed of pilot purpose and duration
- [ ] Parent informed this is supervised internal pilot use
- [ ] Parent consent recorded
- [ ] Parent informed of expected weekly commitment
- [ ] Parent informed how feedback will be collected

## 3) Account Setup Checklist
- [ ] Student account created/verified
- [ ] Parent account linked/verified (if in scope)
- [ ] Tutor/teacher internal support account available (if needed)
- [ ] Correct workspace/role access verified
- [ ] Demo/mock-only paths not used for pilot student accounts

## 4) Device Readiness Checklist
- [ ] Student has at least one supported device (phone/tablet/laptop)
- [ ] Browser is modern and stable
- [ ] MathPath pages load without major layout breakage
- [ ] Question input and submit controls are usable
- [ ] Basic connectivity test passed

## 5) Baseline Test Setup Checklist
- [ ] Baseline diagnostic assigned/run
- [ ] Baseline assessment assigned/run (if available)
- [ ] Baseline starting skill captured
- [ ] Baseline weak skill profile captured
- [ ] Baseline score/time metrics recorded

## 6) Weekly Practice Monitoring Checklist
- [ ] Student completed planned weekly practice sessions
- [ ] Session attempts saved correctly
- [ ] Mastery updates observed after sessions
- [ ] Fluency session completed
- [ ] Retention review due-items tracked

## 7) Outcome Tracking Checklist
- [ ] Weekly mastery growth tracked
- [ ] Weekly fluency changes tracked
- [ ] Weekly retention changes tracked
- [ ] Assessment trend tracked (if assessment run that week)
- [ ] Per-student outcome summary updated

## 8) Bug Reporting Checklist
- [ ] Every blocker logged with reproducible steps
- [ ] Severity assigned (Critical/High/Medium/Low)
- [ ] Screenshot/recording attached where possible
- [ ] Owner assigned
- [ ] Resolution/verification status updated

## 9) Parent Feedback Checklist
- [ ] Parent receives progress snapshot at defined interval
- [ ] Parent can identify child weak areas
- [ ] Parent can identify recommended next action
- [ ] Parent reports if language is clear/confusing
- [ ] Parent confidence/usefulness rating collected

## 10) Pilot Exit Review Checklist
- [ ] End-of-pilot assessment completed
- [ ] Outcome report generated per student
- [ ] Aggregate pilot summary generated
- [ ] Critical issues list finalized
- [ ] Go/No-go recommendation documented

## Pilot Data to Track

Track per student:
- starting skill
- weak skills
- mastered skills
- fluent skills
- retained skills
- practice sessions completed
- questions answered
- average accuracy
- average time
- assessment score improvement
- parent feedback
- student feedback

Recommended weekly tracker fields:
- Week number
- Sessions planned vs completed
- Accuracy trend
- Fluency trend
- Retention due/completed
- Open blockers impacting student

---

## Pilot Success Criteria

Pilot is considered successful when:

1. **>= 80%** of enrolled students complete onboarding.
2. **>= 70%** complete weekly practice expectations.
3. Attempts are saved correctly.
4. Mastery updates correctly after practice.
5. Parents can understand student progress snapshots.
6. No critical bugs block core student practice flow.
7. Outcome report can be generated at pilot end.

---

## Risk Controls During Pilot

- Keep scope to Fractions only.
- Freeze major UI/feature changes during active pilot weeks.
- Triage Critical/High bugs within 24–48 hours.
- Document manual fallback steps for temporary issues.
- Keep clear communication channel for students/parents.

---

## Reporting Cadence

- Weekly internal check-in:
  - completion rate
  - top blockers
  - data integrity status
  - intervention actions

- End-of-pilot package:
  - student-level outcomes
  - aggregate outcomes
  - bug summary
  - recommendation for next phase

---

## Pilot Exit Decision Bands

- **Pass (Ready for larger controlled pilot):**
  - Success criteria met
  - No unresolved Critical blockers

- **Conditional Pass:**
  - Minor criteria miss, but no core flow failure
  - Clear remediation plan and timeline exists

- **No Pass:**
  - Core student flow blocked
  - Outcome tracking unreliable
  - Critical issues unresolved
